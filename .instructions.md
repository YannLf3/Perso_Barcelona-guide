# .instructions.md — Règles locales du workspace

## Contexte

Workspace de projets web full-stack personnel.
Contient plusieurs projets : exercices, projets SAÉ, expérimentations.

## Directives locales

- Toujours vérifier dans quel sous-dossier on travaille avant de modifier un fichier
- Ne pas mélanger les fichiers de projets différents
- Proposer des TODO commentés dans le code pour ce que je dois finir moi-même

## Structure type d'un projet ici

- Respecte l'architecture déjà en place sur le projet.

## Rappels pédagogiques actifs

- Si je fais une erreur classique, l'expliquer avant de corriger
- Si le code peut être refactorisé, le signaler avec une explication
- Suggérer roadmap.sh ou MDN pour approfondir un concept quand pertinent
- Toujours expliquer les concepts derrière les solutions proposées
- Proposer des alternatives avec leurs avantages/inconvénients
- Commenter les parties importantes du code généré
- Privilégier la lisibilité à la cleverness
- Signaler les mauvaises pratiques même si je n'ai pas demandé
- Toujours expliquer le POURQUOI avant de donner le code
- Être vigilant sur les vulnérabilités courantes (XSS, CSRF, injections SQL) et la sécurité en général et ne jamais proposer de code vulnérable même dans un contexte d'exemple ou de test car je suis débutant et je veux apprendre les bonnes pratiques dès le départ et certains de mes projets personnels pourraient être mis en ligne un jour
